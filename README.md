# Light starter

Лёгкий пак для небольших задач: секции и страницы в Figma, дизайн-система в Figma, мелкие правки, одна страница существующего проекта, быстрые HTML-концепты. Работает и в Claude Code, и в Codex. Без кода и установки: это папка-«память» проекта.

Большой сайт на коде, который будет жить по ссылке и расти, — это [site-starter](https://github.com/maksymm-ops/site-starter-max-edition-claude).

## Что внутри

| Файл / папка | Что это |
| --- | --- |
| `AGENTS.md` (+ `CLAUDE.md`) | Правила для агента: режимы, память, экономия токенов, какие навыки брать |
| `PROJECT.md` | Коротко о проекте, ссылки, текущая задача с чек-листом, «ждёт решения Макса», журнал решений. Каждый новый чат читает только его |
| `DESIGN.md` | Дизайн-правила со статусами: утверждено / используется / предложение / устарело |
| `REFERENCES.md` | Все источники с номерами: M — от клиента, R — референсы |
| `inbox/` | Кидай сюда всё новое: бриф, тексты, PDF, логотипы, скриншоты, файл со ссылками |
| `materials/`, `refs/` | Сюда агент раскладывает файлы клиента и картинки-референсы после разбора |
| `out/` | Появляется, только если задача даёт файлы (HTML, экспорт) |
| `.claude/skills/figma-sections/` | Как работать в Figma через figma-console |

## Как начать проект

1. Создай копию: **Use this template** на GitHub или просто скопируй папку и назови по клиенту.
2. Сложи всё, что есть по проекту, в `inbox/`. Ссылки — в любой `.txt`, можно с пометками «нравится / не нравится».
3. Открой папку в Claude Code или Codex и напиши:

```text
Разбери inbox и заполни память проекта.
```

4. Посмотри отчёт: что куда разложено и какие вопросы. Ответь на вопросы — агент допишет память.
5. Дальше — задачи, по одной на чат.

## Главные правила

- **Один результат — один чат.** Закончили и приняли — открой новый чат в этой же папке. Агент сам прочитает память, ничего пересказывать не нужно.
- **Память обновляется после твоего «принято».** Пока результат на проверке, память не трогается.
- **Найденное по дороге агент не делает сам** — пишет в `PROJECT.md` → «Found (waiting for Max)». В конце каждого отчёта одна строка: что добавлено в этот список или «новых находок нет». Посмотри и скажи, что из этого брать.
- **Вопросы — до начала работы.** Если что-то неясно и это меняет результат, агент сразу спросит коротким списком. Мелочи решит сам и отметит как предложение.
- **Новые решения агента — «предложения»**, пока ты их не утвердишь.
- **Одна проверка — и стоп.** Если что-то не проверено, агент так и скажет.
- **Figma:** перед задачей открой файл в Figma Desktop и запусти плагин Plugins → Development → **Figma Desktop Bridge**.

## Промпты

**Пришли новые материалы.** Кинь файлы в `inbox/` и напиши:

```text
Разбери inbox: новые материалы по проекту. Обнови память, покажи, что
изменилось и что противоречит прежнему.
```

**Принять результат и сохранить в память:**

```text
Принято.
```

**Запомнить важное** (решение клиента, правило, факт):

```text
Запомни: [что именно]. Например: «клиент утвердил терракотовый как акцент»
или «тексты только на русском».
```

**Что-то устарело:**

```text
Устарело: [что]. Например: «старый логотип больше не используем».
```

**Изменились требования:**

```text
Клиент изменил требования: [что изменилось]. Обнови память, покажи, что
это затрагивает из уже сделанного. Пока ничего не переделывай.
```

**Агент неправильно понял контекст:**

```text
Ты неправильно понял: [что именно]. Исправь в памяти и скажи, что ещё
на этом было построено.
```

**Секции или страница в Figma:**

```text
Нарисуй в Figma [какие секции / страницу] на странице [название страницы].
Используй стили и компоненты файла. Новое отметь как предложение.
```

**Собрать дизайн-систему в Figma** по утверждённым экранам:

```text
Собери дизайн-систему в Figma по утверждённым экранам [ссылки на кадры].
Переменные, стили текста, компоненты — на странице Design system.
```

**Быстрый HTML-концепт:**

```text
Сделай концепт [первого экрана / страницы] в HTML. Тексты, которые
придумаешь, отметь в отчёте.
```

**Правка страницы существующего проекта** (путь к коду записан в `PROJECT.md` → Links):

```text
Поправь [страницу] в проекте: [что именно]. Сделай точку отката в Git,
одна проверка в браузере.
```

**Разобрать «ждёт решения»:**

```text
Покажи список «ждёт решения». Беру: [номера]. Остальное убери.
```

**Где мы сейчас** (если давно не открывал проект):

```text
Коротко: что в проекте сделано, что утверждено, что в работе и что ждёт моего решения?
```

**Обновить правила проекта из шаблона** (если шаблон улучшился после создания проекта):

```text
Обнови правила этого проекта из свежего light-starter
(https://github.com/maksymm-ops/light-starter): замени AGENTS.md, CLAUDE.md
и .claude/skills/. Память проекта (PROJECT.md, DESIGN.md, REFERENCES.md)
и папки с материалами не трогай. Покажи, что изменилось в правилах.
```

**Проект вырос до сайта:**

```text
Проект вырос до полноценного сайта. Перенеси его в site-starter:
создай копию шаблона, перенеси факты, дизайн-правила и источники
из памяти этого проекта и покажи, что получилось.
```

## FAQ

**Нужно ли в новом чате пересказывать проект?** Нет. Агент сам читает `PROJECT.md`. Просто напиши задачу.

**Нужно ли просить «сохрани контекст» в конце?** Нет. Важное агент записывает сразу, а итог — после твоего «принято». Хочешь что-то закрепить отдельно — «Запомни: …».

**Куда класть референсы-картинки, а куда ссылки?** И то и другое — в `inbox/`. Картинки агент перенесёт в `refs/`, ссылки запишет в `REFERENCES.md`.

**Агент задаёт много вопросов?** Он спрашивает только до начала работы и только то, что меняет результат. Не знаешь ответа — скажи «реши сам и отметь как предложение».

**Можно в одном чате несколько задач?** Можно, но дороже: каждый следующий шаг тянет за собой всю историю чата. Две разные задачи — два чата.

**Работаю то в Claude, то в Codex — что-то нужно делать?** Нет. Память в файлах проекта, оба читают одно и то же.

**Чат стал длинным и медленным?** Скажи «принято» (или «запомни: …» про незаконченное) и продолжи в новом чате.

**Шаблон улучшился — старые проекты обновятся сами?** Нет, у каждого проекта своя копия правил. Используй промпт «Обновить правила проекта из шаблона». Память при этом не трогается.

**Можно удалить README в копии проекта?** Можно, агенту он не нужен. Но с ним удобнее держать промпты под рукой.

## Экономия токенов

- Правила агента — около 1 тыс. токенов, блок «коротко о проекте» — до 400.
- По умолчанию режим Micro: один главный навык, одна проверка, без исследований и помощников.
- Агент не перечитывает то, что не менялось, и не делает повторных похожих скриншотов.
- Большие задачи (много шагов) идут в режиме Standard с коротким чек-листом.
